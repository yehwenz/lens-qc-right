# 光學鏡片檢測系統 — 右件 (R)

純前端的影像辨識檢測工具，透過攝影機即時判斷零件方向是否正確（OK／NG），
NG 時會發出警示聲。使用 [TensorFlow.js](https://www.tensorflow.org/js) 的
MobileNet 特徵擷取 + KNN 分類器，**所有運算與模型皆在使用者瀏覽器本機執行**，
不需要後端伺服器、不會上傳任何影像，因此可以直接部署到 GitHub Pages。

## 部署到 GitHub Pages

1. 建立一個新的 GitHub repository（例如 `lens-qc-right`）。
2. 把 `index.html` 放到 repo 根目錄（或 `/docs` 資料夾）。
3. 到 repo 的 **Settings → Pages**，Source 選擇 `main` branch（若放在
   `/docs` 資料夾則選擇 `/docs`），儲存。
4. 幾分鐘後即可透過 GitHub 提供的網址開啟，例如：
   `https://<你的帳號>.github.io/lens-qc-right/`

> **注意**：瀏覽器的攝影機權限（`getUserMedia`）只在 `https://` 或
> `localhost` 環境下可用，直接用「開啟本機檔案」的方式（`file://`）打開
> 是無法啟動攝影機的。GitHub Pages 預設就是 https，可正常使用。
> 本機開發測試時，可用 `npx serve` 或 VS Code 的 Live Server 之類的工具
> 啟一個本機伺服器再開啟。

## 使用流程

1. **收集樣本**：把零件對準鏡頭，分別點「拍攝 OK 樣本」「拍攝 NG 樣本」，
   每一類建議至少拍 15～30 張、涵蓋不同角度／距離／光線，辨識會更穩定。
2. **模型狀態**：樣本會即時存在瀏覽器記憶體中；可以「儲存到瀏覽器」（存在
   `localStorage`，關掉分頁重開還在），也可以「匯出模型檔案」成一個
   `.json` 檔案，分享給其他電腦或站別「匯入」使用，不用重新拍照。
3. **開始即時檢測**：至少各有 1 筆 OK／NG 樣本即可開始，畫面外框與狀態
   文字會即時顯示 OK（綠）／NG（紅），NG 時會有警示音（可關閉）。

## 之後要做左件 (L) 版本時

這支程式本身跟「左右」無關的邏輯都是通用的（拍樣本、訓練、即時判斷、
存讀模型），左件版本可以直接複製這個資料夾，做以下幾處修改即可：

- `<title>` 與畫面上的「右件 R」文字／badge 改成「左件 L」。
- `STORAGE_KEY`（目前是 `'qc-lens-model-R'`）與匯出檔名
  （`qc-lens-model-R.json`）改成 `...-L`，避免兩邊模型互相覆蓋。
- 其餘（樣本收集、KNN 判斷、警示音、存讀模型）完全不用動。

建議做法：另外開一個 repo（例如 `lens-qc-left`），或同一個 repo 底下用
`/L/index.html`、`/R/index.html` 兩個路徑，各自部署一個 GitHub Pages 網址，
維運上比較清楚也方便各站分開操作。

## 技術重點（給後續維護者）

- **特徵擷取**：`mobilenet.load()` 載入 MobileNetV2，用
  `mobilenetModel.infer(image, true)` 取得 1024 維的中間層特徵向量
  （不是直接用最後一層分類結果），這個向量能代表影像內容特徵。
- **分類**：`knnClassifier` 把每張樣本的特徵向量連同標籤（`OK`/`NG`）
  存起來；辨識時取得目前畫面的特徵向量，找最相近的 K 筆已知樣本用多數決
  決定分類，並回傳信心值。
- **K 值**：程式會自動取 `min(10, OK樣本數, NG樣本數)`，樣本越多、K 值
  上限越高，判斷會更穩定；樣本太少時也能運作。
- **模型儲存格式**：KNN 分類器的「資料集」其實就是每個類別的一個
  特徵向量矩陣（tensor），程式把它轉成純數字陣列（`shape` + `data`）存成
  JSON，讀取時再還原成 tensor，所以匯出的模型檔案其實就是所有訓練樣本的
  「壓縮特徵」，檔案通常幾百 KB 到幾 MB，視樣本數量而定。
- **警示聲**：用 Web Audio API 直接產生一個短嗶聲，不需要額外的音檔案。

## 已知限制／後續可以加強的方向

- 目前判斷完全依賴訓練樣本的品質與數量，樣本沒拍好（角度、光線不足夺）
  準確度會下降，建議正式上線前先用一批已知 OK/NG 的零件測試準確率。
- 若要更嚴謹的良率控管，可以之後加上：
  - 檢測歷史紀錄（時間戳記 + 判定結果 + 縮圖），方便追溯。
  - 信心值低於某個門檻時顯示「不確定」而非直接判定 OK/NG。
  - 多台攝影機／多站別的紀錄集中回報（這會需要一個簡單的後端或雲端
    試算表 API，屬於下一階段可以再規劃）。
