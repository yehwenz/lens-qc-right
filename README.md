# 光學鏡片檢測系統 — 右件 (R)・幾何角度偵測版

跟前一版（TensorFlow.js + KNN，靠拍樣本訓練 AI）不同，這一版改用
[OpenCV.js](https://docs.opencv.org/) 做**幾何角度量測**：直接在畫面上偵測
斜槽那條線的傾斜角度，跟校正好的「正確角度」比對，超出容許誤差就是 NG。

適合你的場景（治具位置固定）的原因：

- **不用拍幾十張樣本訓練**，只要用「正確方向」的零件校正個 3～5 次就好。
- 判斷依據是量出來的實際角度（例如 `-38.2°`），**可稽核、可解釋**，不是黑
  盒子的信心值。
- 治具固定代表零件在畫面上的位置、角度都很穩定，幾何量測會非常準。

> **重要**：這一版把攝影機預覽的「鏡像翻轉」拿掉了，畫面顯示的方向 =
> 程式實際運算的方向，避免操作員看到的畫面跟系統判斷的角度對不起來。

## 部署到 GitHub Pages

1. 建立 GitHub repository（例如 `lens-qc-right`）。
2. 把 `index.html` 放到 repo 根目錄（或 `/docs`）。校正完成後，
   `config-R.json` 也要放在**同一個資料夾**（見下方使用流程）。
3. **Settings → Pages**，Source 選 `main`（或 `/docs`），儲存。
4. 開啟 `https://<帳號>.github.io/lens-qc-right/` 即可使用。

> 攝影機權限只在 `https://` 或 `localhost` 下可用，直接雙擊開
> `index.html`（`file://`）無法啟動鏡頭；GitHub Pages 本身就是 https，沒
> 問題。

## 使用流程

### 第一次設定（找一台電腦、對著治具做一次就好）

1. **設定偵測框**：畫面上已經有一個置中的預設框，也可以點「拖曳設定偵測
   框」自己框出斜槽所在的區域（不用整個零件，框住斜槽內凹的區域即可，
   框越貼合、雜訊越少，判斷越準）。
2. **校正正確角度**：把「正確方向」的零件放在治具上，點「拍攝校正樣本」
   3～5 次。程式會自動算出平均角度與建議的容許誤差（±幾度），也可以自己
   在「容許誤差角度」欄位手動調整（誤差抓太小容易誤判 NG，抓太大則可能
   漏掉真正裝反的零件，建議先用預設值試跑，抓到瑕疵樣本再微調）。
3. **匯出設定檔**：點「匯出設定檔（config-R.json）」下載檔案，跟
   `index.html` 一起放進 repo push 上去。

### 之後任何裝置使用（不用重新校正）

打開網頁時會自動抓同資料夾的 `config-R.json` 套用偵測框與角度設定，狀態
列顯示「已自動載入隨附的設定檔」就代表成功，直接按「開始即時檢測」即可。

### 需要重新校正時

治具調整過、或想換一個更準的偵測框，重複「第一次設定」流程，重新匯出
`config-R.json` 覆蓋 repo 裡舊的檔案、重新 push，所有裝置下次打開就自動
套用新設定。

## 音效提示

跟前一版行為一致：
- **NG**：判定當下發出一聲「嗶——」長音（2 秒），若持續 NG，每 3 秒再響
  一次，直到排除為止。
- **OK**：判定當下發出「嗶‑嗶‑」兩聲短音，只響一次。
- 「音效提示」勾選框可整組關閉。

## 之後要做左件 (L) 版本時

複製這個資料夾（或另開一個 `/L/` 路徑），做以下修改：

- 畫面標題／badge「右件 R」改成「左件 L」。
- `STORAGE_KEY`（`'qc-lens-config-R'`）與 `CONFIG_FILENAME`
  （`'config-R.json'`）改成 `...-L` / `config-L.json`，避免互相覆蓋。
- 校正流程完全一樣：用左件的正確方向零件重新校正一次即可 —— L 件的斜槽
  方向跟 R 件是鏡像的，角度數值本來就會不一樣，不用改演算法。

建議跟前一版一樣，兩個部署成不同的 GitHub Pages 網址，站別上用書籤 /
「加入主畫面」圖示 / QR code 讓員工直接開對的頁面，不需要在同一個網頁裡
切換。

## 技術重點（給後續維護者）

- **抓取畫面**：把目前 `<video>` 影格畫到一個離屏 canvas，用
  `getImageData` 取得像素，再用 `cv.matFromImageData()` 轉成 OpenCV 的
  `Mat`（沒有用 `cv.VideoCapture`，因為那個需要固定綁一個顯示用
  canvas，手動抓幀比較彈性）。
- **偵測流程**：裁切到偵測框範圍 → 灰階 → `GaussianBlur` 降噪 →
  `Canny` 邊緣偵測 → `HoughLinesP` 找直線段 → 取框內**最長**的一條線段
  當作斜槽的邊 → `atan2` 算角度，正規化到 `(-90°, 90°]`（因為線段本身
  沒有方向性，180° 是同一條線，所以角度比較時也要用 180° 為週期處理，
  不能直接用 -angle 或 360°）。
- **偵測框座標**：存成相對於「攝影機原生解析度」的比例（0~1 的
  `x,y,w,h`），不是螢幕像素，所以換不同解析度的攝影機、換裝置螢幕大小，
  只要治具沒動，設定檔還是準的。畫面上是用 `object-fit: contain` 顯示，
  程式有處理對應的信箱化（letterbox）座標換算。
- **判斷邏輯**：`|實際角度 - 目標角度|`（用 180° 週期算差值）超過容許誤差
  → NG；完全沒偵測到夠長的線（例如零件沒放好、根本沒放）也直接判 NG。
- **偵測頻率**：每 200ms 跑一次（`setInterval`），對這種固定治具的單張
  零件檢測夠即時，也不會太吃 CPU。
- **設定檔格式**：`config-R.json` 內容是
  `{ roi: {x,y,w,h}, targetAngle, tolerance, samples: [...] }`，檔案很小
  （幾百 bytes），跟舊版動輒幾百 KB 的 KNN 模型檔比起來輕量很多。

## 已知限制

- 光線變化太大（例如強逆光、反光角度改變）可能讓 Canny 邊緣偵測抓不到
  線，正式上線前建議固定站別的燈光角度，並多測幾次不同時段的光線狀況。
- 目前只取「框內最長的線段」判斷，如果偵測框沒框好、框到零件邊緣的鋸齒
  紋路，可能會誤抓到別的線；框選時盡量只框住斜槽所在的內凹平面區域即可
  避開這個問題。
- 如果之後想要更嚴謹的稽核，可以加上：
  - 每次判定結果的時間戳記 + 角度數值記錄（存在 `localStorage` 或匯出成
    CSV）。
  - 偵測框與角度的即時視覺化（目前只顯示數值，沒有畫出偵測到的線），
    方便除錯與教育訓練用。
